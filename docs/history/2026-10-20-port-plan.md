# DXX-Rebirth: SDL3 platform port + SDL_GPU renderer (GL kept, switchable)

## Context
Rebirth draws with fixed-function OpenGL 1.x (deprecated on macOS) and runs on SDL 1.2/SDL2.
The goal is a **fully playable game on SDL3**, with an **SDL_GPU renderer** (Metal, Vulkan or D3D12)
that can be **switched at runtime against the existing OpenGL renderer**, in the spirit of
Aspyr's Tomb Raider remasters. Every platform supported today must still build and play:
- SDL1.2 builds, `opengl=0`, GLES/RPi and BSD/Haiku stay on GL.
- `sdl3=0` and `sdlgpu=0` are the defaults.

Fork only: `neostar/dxx-rebirth`, on the long-lived branch `sdl-gpu-port`, rebased on upstream
`master` regularly. Upstream house style still applies (tabs, `dcx`/`dsx`, `` `function`: summary ``).

**Settled decisions:**
- Local fork.
- The SDL3 track is planned in full, as its own slices.
- Test seams:
  1. the render device interface
  2. the `rtrace` replayer CLI
  3. pure helpers, tested with Boost
- Shaders are written in HLSL and compiled with SDL_shadercross at a pinned commit; the
  generated headers are committed.
- A deterministic D2 demo recorded with the licensed data may be used, but stays local.

**Facts this plan relies on**, verified in code, docs and measurements:
- SDL2 and SDL3 can't share a source file or a binary: same include guards, same symbol names,
  different ABI.
- SDL3_mixer 3.x is a complete redesign with no compatibility layer.
- SDL_GPU renders headless and reads pixels back
  (`/opt/homebrew/include/SDL3/SDL_gpu.h:33-36, 96-104`).
- SDL_GPU has no fan topology, no line width, no point size (D3D12) and no alpha test.
- Demo playback is bit-identical across runs when the frame time is fixed (measured: 7,667 frames).

## Ways of working (all slices)
- **Size:** at most ~300 changed lines per commit.
- **Commits:** one commit per slice, containing the test and the change. The PR description
  shows the red run, so the branch stays bisectable.
- **TDD:** vertical slices at the three agreed seams only. Expected values always come from an
  independent oracle: the GL adapter, a known-good literal, or the docs.
- **Tooling in every slice:**
  - `compile_commands.json` for clangd and clang-tidy.
  - clang-format on new files only, via a directory-scoped `.clang-format`; upstream files are
    never reformatted.
  - `check_header_includes=1`.
  - An ASan/UBSan builddir.
  - lldb.
  - Xcode Metal debugger / GPU capture; RenderDoc on Linux.
  - SDL `debug_mode` with Metal and Vulkan validation layers.
  - Debug groups per frame section.
- **Review package per slice:**
  - diff size
  - rubric items touched
  - R1 hash line
  - FLIP CSV and heatmaps (synthetic traces only)
  - coverage delta
  - validation count
- **Docs are grounded, not recalled:** `docs/reference/` (gitignored) mirrors:
  - `SDL_gpu.h` and `SDL_hints.h` (3.4.18)
  - SDL3 `README-migration.md` and `README-highdpi.md`
  - SDL3_mixer 3.2.4 `README-migration.md` and its header
  - SDL3_image 3.4.8 migration notes
  - shadercross `README` and `cli.c` at the pinned SHA
  - SDL `test/testgpu*` sources
  - the FLIP README
  - Vulkan validation docs

  ADRs cite them.

### A1. Seam extraction, GL as the first adapter (R1 on every commit)

3. **`common/arch/ogl/gl_device.cpp`:** the GL adapter. It owns the GL state shadow (the

   - `g3_draw_bitmap`

   - `ogl_ubitmapm_cs` (fonts)
   - `ogl_ubitblt_i` (movies)

   R1 stays green after each.
5. **Textures through the device:**

### A2. Trace recorder and replayer
1. **`.rtr` format:** self-contained chunked records (texture bytes included). Reader and writer
   in `common/arch/render/trace.cpp`. Tests: round-trip, plus a malformed-file corpus under ASan.
2. **`recording_device` decorator:** enabled in game with `DXX_DBG_RTRACE=out.rtr[,frames=a:b]`.
   Tested with a fake device.
3. **`tools/rtrace` CLI (`replay|info|coverage|diff`):** SDL3-only; links `gl_device` +
   `sdlgpu_device`. GL runs offscreen:
   - macOS: offscreen CGL context + FBO, no window (proven in spike #55)
   - Linux: `SDL_VIDEO_DRIVER=offscreen` + Mesa llvmpipe

   Prove R2 on S2.
4. **`coverage` + `matrix.toml` (R5).**
5. **Synthetic traces:** C++ generators that call the device API, committed under
   `tests/rtrace/synth/`, each < 64 KB with procedural textures. Their goldens are always produced
   by GL replay, never by hand.

### A3. SDL_GPU adapter, offscreen in `rtrace` (`sdlgpu=1`; one primitive per slice)
**Each slice:** synthetic trace red → adapter code → R3 → R6 → demo-trace R4 once its primitives
exist.

1. **Headless device**, clear, and readback via copy pass + fence + map. Readback comes first,
   because every later test depends on it.
2. **Untextured rects:**
   - fan→list helper
   - ortho helper (unit test against the `glOrtho` matrix)
   - `pos_color_uv` vertex shader + `color` fragment shader
   - pipeline cache keyed by `draw_state`
3. **Textured quad:** RGBA8 upload ring; sampler cache by (filter, wrap, aniso);
   `saturate(vcol) * tex` (GL_MODULATE with clamped colours).
4. **Lit tmap:**
   - perspective recipe with the exact model from spike #55: clip = P·(MV·v), viewport depth 0.5..1, depth clamp + near/far clip distances
   - D32F depth, LEQUAL
   - cull FRONT, with a winding trace on both Metal and lavapipe
5. **Alpha ref:** shader `discard` with a uniform ref, tested at 0.02 and 0.8.
6. **Blends:** normal, additive_a, additive_c, none, and palfx `(ZERO, ONE_MINUS_SRC_COLOR)`.
7. **Depth on/off and the two-pass `tmap_2` overlay:** `precise` position so both passes get the
   same depth.
8. **Lines and points expanded to quads:** helper for `linedotscale` widths, with a unit test;
   pixel-centre rules recorded in an ADR.
9. **Font formats:** fonts uploaded from the game's 8-bit bitmaps as RGBA8/R8 (no INTENSITY4 path on SDL_GPU).
10. **Mipmaps, filters and anisotropy:** per-filter FLIP thresholds, or upload CPU-built mips if GL
    must be matched exactly.
11. **MSAA:** 2/4/8 with resolve, gated by `caps`.
12. **Movies:** a persistent streaming texture instead of create/delete every frame.
13. **S1–S4 traces** meet R4 on Metal and Vulkan/lavapipe; R5 at 100%.

## Windows verification (added 2026-10-20)
Most players are likely on Windows, but the owner has no Windows machine, licence or Windows testers.
Microsoft's free Windows 11 development VMs are x64-only 90-day evaluations, impractical on this
Apple Silicon Mac. So Windows is verified in four layers, none of which needs a Windows licence:

1. **Build (R8):** MinGW cross-build of the sdl3 + sdlgpu game and `rtrace` in the reference
   container, in local CI.
2. **Automated runtime, local:** the Windows `rtrace` build under Wine in the reference container,
   D3D12 translated to Vulkan on lavapipe (vkd3d-proton, or Wine's own vkd3d if proton needs
   Vulkan features lavapipe lacks). Runs R3 synthetic traces and, locally only, R4 scenes. Tests the
   Windows binary and SDL's D3D12 backend, through a translation layer. Open: x64 Wine in an arm64
   container needs Rosetta (OrbStack amd64 image); spike before relying on it.
3. **Real D3D12, deferred** (owner, 2026-10-20: no GitHub CI for now; all CI is local `tools/dev/ci.sh`): a hand-started (`workflow_dispatch` only) GitHub Windows runner runs
   R3 synthetic traces on WARP, Microsoft's software D3D12 rasteriser, with the FLIP gate. Synthetic
   traces only: licensed scenes never reach hosted runners. Open: whether SDL_GPU's D3D12 backend
   accepts the WARP adapter (SDL_gpu.h has no WARP property); verify first.
4. **Playability (R16w):** the owner plays the Windows build under CodeWeavers CrossOver on the Mac
   (D3DMetal or vkd3d), windowed, against the R16 checklist minus Mac-only items. Real Windows
   drivers and hardware stay unverified: recorded as release risk; mitigation is community testers
   once the port is offered upstream.

Spike result (2026-10-20): layer 2 works: SDL_GPU renders pixel-exact under x64 Wine with D3D12 via
vkd3d-proton 3.0.1 and with Vulkan via winevulkan, on lavapipe (Wine's own vkd3d is too old: SM 5.1).
Windows players get D3D12 by default, Vulkan as fallback (SDL_gpu.c:313-327), so ship DXIL and SPIR-V.

## Updates after the port review (owner, 2026-10-22)
- **No in-game renderer switch.** The game starts on the renderer and GPU driver it is given (GL,
  or SDL_GPU on Metal, Vulkan or D3D12) and logs the choice (#50). R13 and scene S5 are dropped;
  #51 is closed. Visual differences are found by R4 on the same scenes, and by eye with a restart.
- **GL is a transition, not a second product.** GL stays the fallback (#52, R14) until SDL_GPU is
  proven; then the fork drops it. Trigger: R16 passed on SDL_GPU, then a period of play without
  SDL_GPU-specific bugs. Dropping GL drops the GL-only targets (SDL1.2, GLES/RPi, BSD/Haiku) from
  the fork.
- **Same look as today.** The port keeps the original assets and look; a "remastered" look is a
  separate project after it, if ever.
- **D1 data** is in `/Applications/D1X-Rebirth.app/Contents/Resources`, D2 also in
  `/Applications/D2X-Rebirth.app/Contents/Resources`; R16 covers D1 and D2.
- **No extra vertical slice.** Spike #55 already proved real game frames on SDL_GPU; what it left
  uncovered (SDL3 window and input) is low-risk and ticketed (#41-#44); #67 was closed. R4's
  "Metal: bit-exact" stays: the spike measured 47/47 game frames bit-exact (Apple's GL runs on
  Metal). The remaining real unknown is performance (R11, #53). Open: an early talk with upstream
  (owner).
- **SDL_GPU track starts after #10** (owner, 2026-10-22). #19 is split: the GL replayer in
  `rtrace` needs only the GL adapter (#10); R2 against the game moved to #68 (after #18, before the
  scene traces #22). From #10 on, two tracks run in parallel: seams in the game (#11-#16, #18) and
  the SDL_GPU adapter on synthetic traces (#19 -> #21/#24 -> #26-#36). About 30 story points come
  off the critical path to the first SDL_GPU shader (#26). Risk: device API changes during
  #11-#16 cost adapter rework.
